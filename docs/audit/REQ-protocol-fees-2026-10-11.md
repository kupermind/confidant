# REQ — protocol fee (Railgun model): net shield/unshield, per-node fee ledger, k-of-N treasury sweep

Sent 2026-10-13 from the implementation session to the audit session, verbatim (PR #23).

```text
REQ (design + impl in one slice): protocol fee in backend/ — branch protocol-fees, PR #23. Owner's request 2026-10-11: Railgun/Tornado economics, a configurable percentage of each operation credited to the pool's operator, set server-side only (never from the UI). Trust-path change (what a node accepts as backed, what a sidecar signs, a new multisigned tx kind), so a ruling before merge. Core untouched.

== Design ==
Policy per node, identical across a quorum: --fee-shield-bps S --fee-unshield-bps U --fee-treasury rT… (FeePolicy::new: each ≤ MAX_BPS = 1000 (10 %); treasury canonicalized through address::canonical and mandatory as soon as either rate is non-zero; rates 0/0 = OFF, behaviour unchanged). Charged on SHIELD and UNSHIELD; TRANSFERS FREE (as Railgun/Tornado; internal hops are what the pool's privacy wants more of).
Shield, net credit: the deposit is gross; fee = ⌊gross·S/10000⌋ (u128 intermediate); the node hands the core DepositRef{delivered: gross − fee} (vouched_deposit, used by submit_shield and endorse(Shield) alike after the screening gate), so the existing binding `delivered == value_balance` forces the wallet to have built the note for exactly the net amount — gross-built or otherwise mis-sized notes are refused by the core as today; no new acceptance path. The wallet learns the rate from the public GET /config.fees.
Unshield, net payout: the note burns gross (the record's value_balance); the node computes fee = ⌊gross·U/10000⌋ and lowers Accepted.payout.amount to gross − fee BEFORE it answers (net_payout; in submit_unshield and in endorse(Unshield), including the idempotent already-applied branch so a replayed endorse reports the same net). The sidecars pin exactly their own node's payout.amount (unchanged rule), so the payout the quorum signs is the net one by construction; the fee simply stays in the pool account.
Accounting: each node keeps FeeLedger{accrued, swept, sweeps: BTreeSet<hash>} at <state>.fees.json (written after every change, like the verifier state); accrue(fee) runs once per newly applied op (submit_* and the applying branch of endorse) — the already-applied branch of endorse never accrues (C3 idempotency extends to the fee). FeeLedger::available = accrued − swept (saturating). GET /fees → FeeReport{shieldBps, unshieldBps, treasury, accrued, swept, available}.
Sweep (the only way fees leave the pool account): coordinator POST /fees/sweep {amount?} (default: its node's available) autofills Payment pool → treasury for that amount, LLS = validated + 20, fans out {txs:[{kind:"fee-sweep", tx}]} to the sidecars (no submission, no memo); a sidecar (signer.mjs) handles kinds === "fee-sweep" by reading GET /fees from ITS OWN node and checkTxShape pins: Account == pool, Destination == its node's treasury (refuses when its node has none), Amount a positive drops integer ≤ its node's available (undefined available → 0 → refused), no Memos, Fee ≤ MAX_FEE_DROPS, Sequence == the pool's next as the sidecar reads it, LLS present and within the payout window. Mixed kinds ([anchor, fee-sweep]) are not in the whitelist → 400. With ≥ k signatures the coordinator submits; after validation it POSTs /fees/swept {txHash} to every node. A node's fee_swept(hash) reads the tx from the ledger ITSELF (Ledger::tx) and sweep_facts pins: validated == true, TransactionType Payment, Account == pool, canonical(Destination) == treasury, meta.delivered_amount an XRP drops string (an IOU amount is refused); then amount ≤ available (else NodeError::Fee → 409), swept += amount, hash inserted; a hash already recorded is a no-op (counted once). LedgerError::Sweep → 422. The coordinator's numbers never reach a signature or a ledger entry: the sidecar trusts only its own node, the node trusts only the ledger.
Replay: rebuild_from_ledger(ledger, pool, mirror, &FeePolicy) → (Verifier, FeeLedger). Shield fees are recomputed from the deposit facts the scan already reads (and the DepositRef passed to rebuild_checked is the net one — so a node rebuilt under a different policy than the one the shields were accepted with REFUSES: `rebuild_checked` sees delivered ≠ value_balance). Unshield fees are recomputed from the replayed records' value_balance; sweeps are summed from the pool's account_tx (sweeps_in: every validated pool → treasury Payment, once per hash). A rebuilt node therefore reports the same accrued/swept as the live quorum (tested in-process and on testnet). CONSEQUENCE, documented everywhere (SPEC §6 EN/RU, NODE-OPERATOR, deploy README, ROADMAP §7): the fee policy is a genesis constant of a pool; changing rates = a new pool (a fee epoch in the anchor memo would lift that — roadmap, memo-format change → core slice). Nodes with different policies also diverge in roots (net notes) and refuse each other's memos, so a misconfigured node fails closed rather than signing.
Setup/deploy: setup-pool.mjs funds a treasury account (treasury.key.json 0600, config.treasury, config.fees; FEE_SHIELD_BPS/FEE_UNSHIELD_BPS env, default 25 bps each — the demo rate); launchQuorum/start-all/render-env/systemd pass --fee-* to every node (FEE_ARGS). A node started with a non-zero rate and no treasury exits at startup. Startup log: "fees: shield S bps, unshield U bps, treasury rT…; accrued/swept/available" or "fees: OFF".
UI/holder side (FYI, no slice): frontend/index.html reads /api/config.fees, builds the shield note for gross − fee, shows "note X XRP after the Y % fee" and the net payout from Accepted.payout.amount; nothing about fees is configurable in the UI. backend/wallet (demo service) unchanged: it builds whatever amount the page asks for.
Honest label (SPEC/README): the fee is a public, verifiable operating policy of the pool (every shield, unshield and sweep is on the ledger and in the log); not a privacy feature; the treasury is an ordinary XRPL account under the same k-of-N custody caveat as the pool account.

== Residuals ==
R1 Policy is a genesis constant: a rate change makes replay refuse earlier shields (by design: the binding is the fee's only enforcement point). Operators get a new pool for new rates; a memo-carried fee epoch is roadmap and would be a core slice.
R2 The fee ledger is per node and derived; it is not part of the anchored root. Two honest nodes agree because both derive it from the same ledger facts + the same policy; a node with a stale ledger view could briefly report a lower `available` and refuse a sweep (fail-closed), never sign one above what it accounted.
R3 Sweeps are explicit operator actions (POST /fees/sweep is unauthenticated like every coordinator endpoint, but it can only move fees to the treasury the sidecars' own nodes know — a stranger can at most trigger a legitimate sweep).
R4 Rounding: ⌊·⌋ per operation; dust below 1/bps of a drop is never charged (favours the user).
R5 The treasury's custody = the operators' XRPL key(s); the pool's "k signers can drain the pool account" caveat now also covers the fees before they are swept.
```
