A technology · applications are built on it

A TEE co-processor — not an L2, not a chain.

TRUST runs the work a smart contract would do inside attested enclaves, signs with an M-of-N threshold (FROST / MuSig2) that assembles no key in one place, and settles on the chain’s own native primitives — multisig, atomic tx, on-chain data. Code updates activate only when the operator quorum signs a new measurement. Phoenix, XPerp and the bridge are applications of this engine; the next one plugs into the same stack.

// 02  Composition — three primitives

Remove one and it collapses

Mutually reinforcing, not additive. Drop any one and TRUST collapses into something that already exists — a consortium chain, signing-as-a-service, or attested SaaS compute.

01

Native chain primitives

M-of-N multisig + atomic transactions + on-chain data field + public verifiable ledger. Whatever the chain natively exposes — P2WSH/P2TR, SignerListSet, OP_RETURN.

02

TEE-attested business logic

Matching, settlement math, threshold signing inside hardware-isolated enclaves, measured and remotely attested. Keys never leave silicon.

03

Code / operator separation

Cryptographically enforced. Operators control which code runs without controlling what each operation does — reproducible build → the quorum admits a measurement.

// 05  The differentiator

Decentralized from genesis: the update is a threshold ceremony

Most systems decentralize custody but keep a centralized upgrade path — an admin key or a git push that silently changes what every node runs. That path is the one TRUST closes first.

Any change to the enclave code changes its measurement, and the new measurement is admitted only by a quorum ceremony of the physical nodes — the same t-of-n authority that governs funds. Builds are reproducible, so independent operators each rebuild to the identical measurement before they consent. No admin key, no out-of-band push — for every build, test versions included.

// 06  Trust model & trade-offs, declared

“Trustless” is wrong — the truth is specific

What you trust

  • + Enclave manufacturer — the same trust as your own CPU; a per-deployment choice
  • + Reproducible-build pipeline — verifiable by independent operators
  • + Operator quorum — quorum-gated updates, quorum-signed payouts

What you don’t

  • − The dev team — can’t ship code the quorum didn’t sign
  • − Any single operator — no one moves funds or changes code alone
  • − Bridges, wrapped tokens, off-chain custody

Not a strict improvement — a different trade-off point

  • On-chain composability is lost. No flash loans or contract-to-contract calls; bridges needed for cross-protocol.
  • Public state auditability is lost. Privacy is the feature; code attestation stays public via reproducible build.
  • Liveness is compound (chain AND quorum) — but every withdrawal has a time-locked cancel_after; funds are never quorum-captured.
  • Chain coverage is aspirational — ships BTC + XRPL today; each new chain is a per-chain port.
